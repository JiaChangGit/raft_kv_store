# 這個專案怎麼和 AI 一起做

這個專案的程式、測試、規格、教學與報告，幾乎都是 AI 模型寫的。作者決定要做什麼、核准每一份規格、抽查結果，並保留所有對外的操作（push、建立 PR、部署）。
這份文件說明分工、每個階段的流程、用了哪些模型、獨立審查找到什麼，以及這個做法的限制。原始紀錄在[框架經驗紀錄](FRAMEWORK_EXPERIENCE_LOG.md)與各階段的規格補記。

## 分工

| 誰 | 做什麼 |
|---|---|
| 作者 | 訂目標與範圍，例如 2026-11-15 把計畫縮減成「只做做得出來的事和重點功能」；核准每個階段的規格；抽查評分與標註（S7 抽查 10 筆標註、S8 抽查 3 筆評分）；決定框架要不要改；自己 push |
| AI | 起草規格與可選的做法、寫程式與測試、跑驗收、寫 bug 教學與報告；和框架有關的經驗當下記進紀錄 |

AI 每次停下來問作者的，都是會改變結果、又沒辦法從材料確定的事：要不要縮減範圍、選哪種儲存格式、框架要不要一起改、授權條款用哪一種。

## 每個階段的固定流程

路線圖定了每個階段都照這個順序做：寫規格（含不保證的事）→ 作者同意 → 先寫會失敗的測試 → 實作 → 模擬與故障測試 → 獨立審查 → 寫教學 → 跑驗收、留下 receipt → 本機 commit 與 tag → 停下來讓作者提問。
tag 只在驗收全部通過之後建立，所以 tag 存在本身就是一個查得到的證據。2026-11-16 起，規格還要寫明「模型分工」：哪一步由哪個模型或子代理做；沒寫進規格的分工，執行時常被跳過。

| 階段 | 寫規格與實作 | 獨立審查 |
|---|---|---|

| S6～S9（2026-11-15～16） | `claude-opus-5-5` | S6 處理的就是 S5 審查的發現；S8 後續的框架修改由 `claude-sonnet-5-5` 審查 |

## 獨立審查找到什麼

- **S1～S4**（[報告](INDEPENDENT_REVIEW_S1_S4.md)）：沒有找到違反 Raft 安全性的缺陷。找到一個 S2 的回復缺陷（教學 11）、一個 S4 讓模擬器的檢查退步的問題（教學 12）、一個 S2 的邊界缺陷（教學 13），都修好後重新驗收。
- **S5**（[報告](INDEPENDENT_REVIEW_S5.md)）：列出 F1～F7。其中 F6、F7 讓驗收根本跑不完，而文件已經寫成完成；F2～F5 在 S6 補上測試與修正（教學 16～19）。
- **S8 後續**（[結果](../framework-study/changes/RESULTS.md)）：框架分支的 10 項問題，包括一支統計工具會把任意字原樣輸出，以及權限說明寫了沒有測過的行為。

## bug 教學從哪裡來

[19 篇教學](lessons/README.md)都是開發中真的遇到的 bug，每篇都有可以執行的重現、當時的輸出與修正前後的程式。寫法由專案自己的 `write-bug-lesson` skill 規範：根因確認之前不寫，練習題的答案先實際跑過再寫。
這些教學都還是草稿，因為還沒有第二個人照著做過一遍。

## 用來做這個專案的框架

作者有一套自己的 AI 工作框架（ai-general-framework）：幾個專用的 skill、按需閱讀的指引，以及共用的小工具。本專案部署了其中 5 個 skill。分析這套框架也是專案的目的之一：

- **S7**（[報告](../framework-study/zh-style/report.md)）：檢查文件裡的中文「AI 味」。規則式提示的精確度約 17%，估計只找得到約 4% 的問題，所以只能當提示，不能當門檻。
- **S8**（[報告](../framework-study/analysis/report.md)）：照作者列的 11 項標準逐項分析，另做三個對照實驗（33 次全新的無頭 session）。主要發現：在 Claude Code 上，skill 從沒經由 Skill 機制被叫用；專案原本就有 `CLAUDE.md` 時，框架的規則沒有接上；交接文件對較強的模型有用，較弱的模型會照抄結論。
- **S8 後續**（[結果](../framework-study/changes/RESULTS.md)）：依報告修改框架：規則入口的檢查、交接要寫接手者自己執行的核對命令、Claude Code 的權限範本、評測工具，以及 skill 叫用的措辭。量測與審查之後，併進框架的 main。

## 這個做法的限制

- **寫的和評的常是同一個模型。** 盲評交給看不到組別的子代理，但它和作者用的是同一個模型；作者只抽查了少數幾筆。
- **實驗每個條件只跑一兩次。** 差異可能是雜訊，結論只能當方向。
- **教學沒有真人照做過。**
- **專案的權限設定曾經整段沒有生效。** 專案的 `.claude/settings.json` 擋框架目錄的寫入與 push，但 session 從上一層目錄啟動時，這份設定不會載入（2026-11-16 實測，經驗紀錄 L59）。在那之前，「框架唯讀」「不 push」都只靠模型自己遵守；之後規則也放進了啟動目錄的設定。
- **能自動檢查的才可靠。** 經驗紀錄裡重複出現的錯（`pkill -f` 殺掉自己的 shell、commit 訊息寫了沒算過的數字）都寫過提醒，照樣再犯；真正擋住的是可以執行的檢查，例如驗收契約、mutation 測試與預檢腳本。
